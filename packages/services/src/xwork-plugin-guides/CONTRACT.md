# XWork plugin guide service

The target Host owns accepted requests, real stream projection, the latest complete guide, its question/answer history and any pending unsaved revision. Renderer owns navigation, an unsent question and the next request's model/reasoning choice. No ordinary task, plugin install/enable or session setting is created or changed. Public index/contract are browser safe; Node assembly is separate.

Source identity, plugin ID, locale and template version locate one latest document; authoritative source revision and verified content fingerprint detect staleness. Workspace identity (path fallback) and attachment route select a projection, never a second persisted truth. First generation is single-flight; a cross-process document lock covers reread/generation/save so a second initial opener reuses the committed result.

Before streaming, the Host reads its model-selection facade, defaults to the preferred identity with the first public reasoning level, and validates the request-local choice through the same facade. Missing, unavailable or normalized provider/model/reasoning choices fail without replacing saved content. Accepted requests pin that choice; completed documents persist the executor's actual selection alongside provider/model metadata. Old documents without selection remain readable. Selection reads never mutate ordinary session preferences, drafts, Recent or account connections.

Reads and phase transitions publish full snapshots; streaming changes append only new reply/Markdown text. Both share one monotonic sequence. A missing operation/base or sequence gap is repaired by reading this owner, never by generating again. Preview limits are checked before mutating or publishing state; invalid partial output cannot poison later snapshots.

Source and stream adapters own a 30-minute abort deadline, followed by a protocol watchdog with a five-second buffer. Cancellation therefore clears the protocol request without triggering workspace-agent recycling. Material reads receive the operation signal. The shared filesystem-lock helper has no abort argument: a contended lock can delay cancellation until acquisition or the existing 180-second lock timeout, with an abort check before model invocation.

Only an actual successful model finish plus seven complete ordered sections can become a new revision. Abort, provider failure, truncation or invalid format preserves the predecessor. Atomic save failure retains the candidate for write-only retry. Retry compares the saved predecessor revision under the same lock to prevent overwriting a newer window revision. Repository save is called only inside its document lock, so the inner atomic write must not acquire that lock twice.

Plugin materials are untrusted; the CLI adapter sanitizes secret values and authorizes all document reads. The service never reads project files or ordinary conversations. The real model request uses current Host model/auth/admission and returns actual usage. Existing best-effort model_usage persistence cannot record a temporary workspace call lacking a persisted session row; this extension does not create a hidden task or migrate usage storage to conceal that limitation.
