# Plugin guide reader

`XWorkPluginStoreDetailView` composes the existing plugin detail through its optional generic `headerActions` slot. It adds an independent reader without installing, enabling or creating ordinary tasks. Returning retains the mounted detail and its controls.

The target Host's optional `IPluginGuideService` owns saved guides, accepted question history and generation. UI holds navigation, unsent text and a reader-local model/reasoning selection. Management supplies its resolved service explicitly; `null` never falls back to another Host. The reader subscribes before reading, accepts only its exact target and monotonic sequence, and detaches without cancelling on navigation. Only an idle empty read starts automatic generation. Regeneration, questions, stop and saving retries are explicit service commands. `generate(question?, regenerate?, selection?)` forwards the local choice only for manual model requests; changing that choice never replaces the guide subscription or automatically generates.

Desktop and mobile consume the same Host snapshot/preview union. The hook subscribes before reading, appends only consecutive deltas for the current operation, and repairs a missing base or sequence gap with a read. Reopening reads the owner snapshot; these events do not enter ordinary task replay. Markdown uses the existing theme/code-preview renderer. Questions use the main ChatPromptEditor shell and merged ModelConfigSelect model/effort menu, with task slash commands, mention panels and file paste/drop disabled. The model catalog is the guide Host's own `modelSelectionService`, taken from the same resolution as the guide service (`modelSelectionService` and `guideHostReady` beside `guideService`; the context services supply both when neither is given). It is never re-resolved from the target path, so a Source or a remote workspace without an attached tab cannot show another Host's models. Saved supported selections restore, otherwise the preferred identity starts at its lowest public reasoning level. Catalog changes invalidate an existing choice instead of replacing it. A ready or unsaved completion clears only the same unchanged input owned by the same mounted reader; errors, cancellation and stale results retain it.

`contract.test.ts`, `packages/ui/test/xworkPluginGuideModel.test.ts`, `packages/ui/test/xworkPluginGuideHostBinding.test.ts` and `packages/ui/test/xworkPluginGuideQuestions.test.ts` cover the service projection, local selection and shared Composer behavior. Main integration runs tests, typecheck, lint and architecture checks after all slices land.
